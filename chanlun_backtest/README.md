# 阿娇版缠论 —— 数字货币真实胜率回测

本目录用**严格因果式（无未来函数）**的方式，实现了"阿娇版缠论"（即缠中说禅《教你炒股票》
108课体系）中最核心的可执行规则——笔、中枢、背驰、三类买卖点，并在 **PEPEUSDT / ORDIUSDT /
ZECUSDT**（三个波动特征完全不同的币种：持续阴跌、深跌+逼空、真实暴涨十倍）过去 **1 整年**
（2025-06-01 ～ 2026-05-31）的 **1分钟 / 5分钟 / 30分钟** K线上做了真实回测，统计真实胜率、
盈亏比与收益曲线，并做了单周期 vs 多级别联立、以及多币种之间的对比。过程中还专门做了一轮
"找逻辑依据、找逻辑漏洞"的深度检验：真实发现并修复了两个代码 bug（三类买卖点方向判断错误、
一类买卖点背驰比较对象用错，均此前从未被正确实现），并用随机基线蒙特卡洛对照、持仓时长
分布、原著逐字重读交叉验证等方法验证了买卖点信号与核心理论机制的统计显著性。**全程不含
任何止损/仓位管理**，纯粹按缠论买卖点信号机械反手交易。

- PEPEUSDT 详细结论见 [`RESULTS.md`](./RESULTS.md)
- PEPEUSDT vs ORDIUSDT 双币种对比见 [`COMPARISON.md`](./COMPARISON.md)
- **逻辑依据与逻辑漏洞深度检验（含三类买卖点 bug 修复、随机基线显著性检验、ZECUSDT
  牛市对照、whipsaw证据）见 [`LOGIC_ANALYSIS.md`](./LOGIC_ANALYSIS.md)——建议优先阅读**
- **SMC（Smart Money Concepts：失衡区/订单块/结构突破）审查、重写与实测对照见
  [`SMC_ANALYSIS.md`](./SMC_ANALYSIS.md)**——审查了一版用户提供的 SMC 代码（发现分块
  边界断档、未来函数、订单块方向定义矛盾三个实质性 bug），按同一套因果性标准重写后
  实测：SMC 信号胜率在全部 54 个"数据集×子集"组合上无一例外显著低于随机基线，
  与缠论买卖点组合确认后胜率提升但会误伤贡献主要收益的关键信号
- **缠论"基本逻辑"本身是否成立的独立验证见 [`BASIC_LOGIC_VALIDATION.md`](./BASIC_LOGIC_VALIDATION.md)**——
  把"笔/中枢构建是否自洽""背驰能不能预测反转""中枢是不是真的震荡消化"这三条理论
  断言从"买卖点信号能不能赚钱"这个复合问题里剥离出来单独检验：结构自洽性和"中枢=
  震荡消化"两条**统计基础极其扎实**（9/9数据集、汇总p值≈0），但"背驰能预测反转"
  这个买卖点体系的核心机制，在标准操作化定义下**9/9数据集均未通过显著性检验**，
  换6种主流"力度"量化方式重新验证依然不成立（18组检验17组不显著）；回头逐字重读
  缠中说禅原著后，进一步发现"背驰"此前的比较对象实现有 bug（隔一笔代替真正的中枢
  进入笔），修复后用理论上正确的中枢锚定定义重新验证，**结论依然不成立**，同时修复了
  `chanlun_engine.py` 里真正用于生成交易信号的实现，全部回测结果已用修复后的引擎重跑
- **"小转大"（缠论级别的结构递归定义）检验见 [`DUAN_CONFLUENCE.md`](./DUAN_CONFLUENCE.md)**——
  之前多级别联立用固定时钟K线重采样代理"级别"，这里新增线段（`duan_engine.py`，
  标准特征序列法）构建纯结构递归级别，发现"固定时钟级别方向"与"结构递归级别方向"
  平均只有约66%一致（即约1/3时间方向相反）；换成结构递归级别联立后，胜率普遍
  略有提升，但累计收益率在6组测试里5组明显更差（过滤掉了贡献主要收益的大盈利交易）

## 复现方法

```bash
pip install czsc pandas numpy pyarrow requests

# 1. 下载数据（可换任意币种/区间，脚本对 symbol 完全通用）
python download_data.py PEPEUSDT 2025-06 2026-05
python download_data.py ORDIUSDT 2025-06 2026-05
python download_data.py ZECUSDT 2025-06 2026-05

# 2a. 跑三个周期各自独立的回测（默认手续费单边 0.1%，即双边 0.2%）
python run_backtest.py --symbol PEPEUSDT --freqs 1m 5m 30m --fee 0.001
python run_backtest.py --symbol ORDIUSDT --freqs 1m 5m 30m --fee 0.001
python run_backtest.py --symbol ZECUSDT --freqs 1m 5m 30m --fee 0.001

# 2b. 跑多级别联立回测（30分钟定方向->5分钟找买卖点；5分钟定方向->1分钟找买卖点）
python run_backtest_multilevel.py --symbol PEPEUSDT --fee 0.001
python run_backtest_multilevel.py --symbol ORDIUSDT --fee 0.001
python run_backtest_multilevel.py --symbol ZECUSDT --fee 0.001
```

## 为什么选择 PEPEUSDT

用户要求"找一个不太稳定的数字货币"。PEPEUSDT 是市值较大、但价格波动剧烈的 meme 币：

- 测试区间内日收益率标准差 **5.3%**，年化波动率约 **101%**
- 单日最大涨幅 **+27.8%**，单日最大跌幅 **-27.5%**
- 区间最高价/最低价比值达 **5.29 倍**
- 买入并持有整年的收益率为 **-70.6%**（区间内经历了完整的大涨大跌周期）

## 第二个对比标的：ORDIUSDT

为了检验结论是否只是 PEPE 这一个币种的偶然结果，额外挑选了年化波动率更高（约198%，接近
PEPE 的两倍）、且波动"方式"明显不同（PEPE 持续阴跌，ORDI 中途出现过单周暴涨超过 250% 的
极端拉升）的 **ORDIUSDT** 做同样口径的完整回测。完整对比结论见 [`COMPARISON.md`](./COMPARISON.md)，
核心发现：

1. "周期越长、胜率越高、回撤越小"在两个币种上都成立；
2. 多级别联立在两个币种上都稳定有效，能把亏损的单周期策略转为盈利；
3. **ORDI 因为波动中夹杂剧烈单边脉冲，暴露出"无止损裸空"策略在这类标的上的毁灭性风险**——
   单笔交易亏损可以超过 100%（即理论上的"倒欠"仓位），这个现象在 PEPE 测试中完全没有出现，
   只有通过跨币种对比才能发现。

## 第三个对比标的：ZECUSDT（真实暴涨十倍的牛市）

为了检验"卖点更可靠"是否只是"该测试区间恰好是熊市"的巧合，额外挑选了测试期内**真实上涨
+971.58%**（十倍）的 **ZECUSDT** 做对照（Zcash 2025年11月的"隐私币叙事+机构增持"行情，
数据已与公开新闻/行情站点交叉核实，确认真实可信）。核心发现见 [`LOGIC_ANALYSIS.md`](./LOGIC_ANALYSIS.md)
第5节：ZEC 上多头系统性优于空头（收益率维度），与 PEPE 上空头系统性优于多头正好方向相反、
互相印证——**说明"顺大势方向"才是本质规律，不是"缠论卖点天生比买点可靠"**；但即便如此，
不做趋势方向过滤的机械反手策略依然无法跑赢买入持有，凸显了"信号方向判断力"与"能否真正
吃到趋势收益"是两回事。

## 找逻辑依据、找逻辑漏洞：一次深度代码与统计检验

在完成三币种回测后，专门做了一轮更深入的检验（完整过程见 [`LOGIC_ANALYSIS.md`](./LOGIC_ANALYSIS.md)），
包括：

1. **真实发现并修复了一个代码 bug**：三类买卖点（三买/三卖）的"离开中枢方向"判断用错了
   变量（用笔自身涨跌方向代替离开笔的几何位置），导致三类买卖点在所有此前测试的币种和
   周期上都从未真正触发过，插桩统计显示这个 bug 在满足几何结构条件的全部样本上**100%
   必然触发**。修复后重新跑了全部回测（本仓库当前的数字均为修复后版本）。
2. **随机基线蒙特卡洛显著性检验**：证明缠论买卖点的**胜率**在全部 9 个"币种×周期"组合上
   都显著低于同等交易笔数的随机开平仓基线，但**收益率**在其中 5 组显著优于随机基线——
   说明这套规则赢在"赔率"而非"胜率"。
3. **持仓时长分布分析**：证明 1分钟/5分钟周期的亏损交易普遍是"刚开仓下一根K线就被打脸"
   （中位持仓时长 0分钟），30分钟周期这个现象消失，为"周期越长表现越好"提供了微观机制解释。
4. **二类买卖点的隐藏设计缺陷**：在"逢信号必反手"的执行框架下，二类买卖点因为定义上
   紧跟同方向的一类信号，导致仓位已经同向、100% 无法触发实际交易——是一个"信号被正确
   算出但被执行层悄悄阉割"的隐蔽陷阱。

## 无未来函数的关键实现细节

1. **笔的构建**完全交给 `czsc`（`rs_czsc` Rust 内核），这是一个逐根K线增量更新
   （`c.update(bar)`）的流式算法，天然因果。
2. **已发现并修复的未来函数陷阱**：`bi_list` 的**最后 1 个元素是"延伸中"的临时笔**，
   会随着新K线到来被原地修改甚至撤销（回退）。若直接用它判断买卖点，等于提前用到了
   "未来才会最终确定"的信息。修复分两层：
   - **安全冗余**：只使用 `bi_list[:-2]`（丢弃最新 2 笔）作为"绝对确认、不会再变"的
     笔序列，用它构建中枢、判断背驰、生成买卖点；
   - **运行时自证（而非一次性抽样测试）**：`ChanEngine.run(verify=True)`（默认开启）
     在**每一次实际回测运行、覆盖全部K线**时，持续比对相邻两次轮询中同一下标笔的
     指纹（起止时间+价格+方向），一旦发现 `bi_list[:-2]` 假设被打破就立刻抛出
     `RuntimeError` 并报告需要的最小冗余，而不是静默产出被未来信息污染的结果。
     `run_backtest.py` 在捕获到该异常时会自动加大冗余重跑。
   - **验证结果**：1分钟/5分钟/30分钟三个周期的**全年全部K线**均已完整跑过自证，
     `max_retraction_observed = 0`（即在验证覆盖的全部轮询点上从未观察到任何回退），
     `safety_margin=2` 的假设被完整证实，详见 `RESULTS.md`"运行时自证结果"一节。
3. **交易执行价 = 信号被程序发现那一刻所在K线的下一根K线开盘价**，而不是信号对应笔端点历史时刻
   的下一根K线——避免"程序批量轮询才发现信号，但拿信号发生时刻的价格成交"这种隐蔽的未来函数。
4. 中枢、背驰、三类买卖点的具体规则定义见 `chanlun_engine.py` 顶部注释与 `RESULTS.md`。

## 已知局限（务必阅读）

缠论本身在业界公认**依赖交易者主观判断**，不同人对"背驰""三买三卖"的具体量化方式存在争议
（这也是为什么会有"阿娇版"这样的民间注解版本帮助初学者理解）。本回测采用的是一套自洽、
在代码中完全公开、可复现的量化规则，但**不代表"缠论"或"阿娇版缠论"唯一正确的算法化实现**。
更换规则细节（例如背驰的判定阈值、中枢构建方式、止损止盈规则）会显著改变回测结果。

**当前版本完全没有止损/仓位管理**（按用户要求暂缓加入），这不是一个可以忽略的细节：
ORDIUSDT 的回测中已经真实出现了单笔亏损超过 100% 的"裸空爆仓"交易（详见
[`COMPARISON.md`](./COMPARISON.md) 第4节），说明在真实波动更剧烈的标的上，机械反手而不设
止损的做法有理论上无限的下行风险，本回测的收益率/回撤数字**不能**直接当作可实盘复现的
资金曲线，仅用于比较不同周期/标的/联立规则之间买卖点信号本身的方向判断力。
