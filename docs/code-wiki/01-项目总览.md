# 项目总览

## 1. 项目定位

从当前工作区源码看，这个仓库主体不是一个简单的前端应用或普通 CLI，而是一套完整的“智能编码代理运行时”，主要能力包括：

- 终端交互式 REPL / TUI
- 命令系统与 slash command
- 工具调用系统
- 查询引擎与消息循环
- MCP server 暴露与 MCP 客户端扩展
- 远程控制 / bridge / remote session
- 插件、技能、后台任务与多代理协作

根目录 `README.md` 对它的概括也与上述一致：包含 agent orchestration、tool implementations、API service layer、MCP、permission system、CLI transport 与 prompt construction。

## 2. 仓库组成

当前仓库实际上包含两部分：

### 2.1 主 TypeScript 系统

这是仓库主体，分布在根目录及多个 TS/TSX 目录中，例如：

- `entrypoints/`
- `commands/`
- `components/`
- `hooks/`
- `state/`
- `services/`
- `bridge/`
- `remote/`
- `skills/`
- `plugins/`
- `utils/`
- `ink/`

### 2.2 独立 Python 子项目

目录 `chanlun_backtest/` 是一个可单独运行的数字货币缠论回测项目，包含：

- K 线下载
- 缠论引擎
- SMC 引擎
- 回测撮合
- 多级别联立实验
- 随机基线与逻辑验证脚本

它不是主 TypeScript 运行时的一部分，应视为同仓库下的独立研究子项目。

## 4. 应用形态

这个仓库不是单一运行模式，而是多形态运行时：

1. 交互式 CLI/TUI
   - 通过终端 REPL 与用户交互。
   - 典型入口是 `entrypoints/cli.tsx` 进入 `main.tsx`。

2. 非交互式 headless 模式
   - 支持 `-p/--print` 等非交互路径。
   - 同一核心查询链路复用 `QueryEngine` 与 `query()`。

3. MCP server 模式
   - 通过 `entrypoints/mcp.ts` 将内部工具暴露为 MCP server。

4. 远程控制 / bridge 模式
   - 支持 `remote-control`、`remote`、`bridge` 等路径。

5. 后台会话 / daemon 模式
   - 支持后台 session 管理、attach、logs、kill 等。

## 5. 主执行链路

可以把主系统理解为下面这条主链：

```mermaid
flowchart TD
  A[entrypoints/cli.tsx] --> B[main.tsx main()]
  B --> C[run()]
  C --> D[getCommands()]
  C --> E[getTools()]
  C --> F[init()]
  C --> G[REPL 或 非交互执行]
  G --> H[QueryEngine.submitMessage()]
  H --> I[processUserInput]
  I --> J[query()]
  J --> K[工具调用 / 命令执行 / MCP / 子代理]
  K --> L[AppState 更新]
  L --> M[UI / bridge / remote 同步]
```
